The Big Number
74%
of R scripts in published reproducibility packages
failed to run in a clean environment

Trisovic and coauthors pulled more than 9,000 R scripts from over 2,000 packages on Harvard Dataverse and tried to run each one on a fresh machine. Same code, same data, nothing changed. 74% hit an error. Usually something small: a working directory pointed at someone’s laptop, a package that never got installed, a file the script expected that wasn’t in the folder. When they automatically fixed just the paths and the package installs, the failure rate dropped to 56%. That’s computational reproducibility. Can someone else run your code on your data and get the paper’s results? It’s the check the Reproducible Research team does on every PRWP package, and most of the failures are things you can find yourself before you submit.

Source: Trisovic, Lau, Pasquier & Crosas, A large-scale study on research code quality and execution, Scientific Data (2022)  ·  code and data

The Reproducibility Skill

Catch a failed run before the reviewer does

Those Dataverse scripts failed for the same reasons Bank packages fail. A path that only works on one laptop. A package nobody installed. A file the code expects that isn’t in the folder. We developed a skill that looks for those problems in your project. Worth being precise about the words. Computational reproducibility means someone else runs your code on your data and gets the same exhibits. That’s different from rebuilding the analysis from the paper (Field Notes covers that). And a package that runs can still be the wrong analysis.

The skill is built on the checks the Reproducible Research team actually uses when they verify a PRWP package. It has four phases. The first one, the Audit, is read-only. It looks through the folder the way a reviewer would and reports what would break a clean run. It doesn’t rewrite anything.

What it finds is familiar. Dropbox paths. No main script. Missing seeds. Packages the code uses but never installs. Tables pasted in by hand. Data files the code reads that aren’t in the folder. Same class of problems that sent 74% of those Dataverse scripts off the rails, and the same ones that send Bank packages back for another round.

That’s all it claims to do. It won’t tell you if the regression is the right one, if the sample matches the paper, or if a merge quietly doubled the observations. A colleague reading the code will catch those. The audit won’t. Later phases can propose fixes and re-run the package, but only after you’ve looked at the report.

So the useful first move is just the audit, on a project you already have. That’s the 10 minutes below.

Materials: setup guide  ·  slides  ·  latest skill release  ·  demo project

Try This Today  ·  10 minutes

Take a project you’re working on and run the skill’s Audit phase. Don’t let it change anything yet. Just ask whether it would run on someone else’s machine.

1. Open VS Code and confirm that GitHub Copilot or Claude Code responds in the chat panel. The setup guide covers both options.
2. Download the latest skill release. Unzip it and place the full reproducibility-skill/ folder under .agents/skills/ in the project root.
3. Open your project in VS Code. If you prefer to practice first, download the optional demo project and leave its folders unchanged.
4. Ask your coding agent:

Use the reproducibility skill to audit this project. Complete the Audit phase only. Report each finding with the file, evidence, and requirement it relates to. Do not change files.

Pick one flag, open the file it cites, and check it. Is it real, unclear, or a false alarm? When the agent asks to go on to Outline, stop there.

Have more than 10 minutes? Read the rest of the report. Some flags would stop the run (paths, missing files). Some would change the numbers (seeds, hand-edited tables). Some just make the package harder to follow. The Deep Dive walks through the report.

Field Notes  ·  beyond the trainings

Replication is a different problem

Kubota and coauthors gave an AI system a published paper, the raw survey data, and the codebook. No code. They asked it to rebuild the tables from the text. For one table it tried 100 times and still got sample sizes and significance levels that didn’t match.

That’s a different job from the audit. Field Notes walks through what the system actually did, and why the leftover gaps are still useful.
