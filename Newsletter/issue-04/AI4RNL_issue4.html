The Big Number
74%
of R scripts in published reproducibility packages
failed to run in a clean environment

Trisovic and coauthors downloaded more than 9,000 R scripts from over 2,000 reproducibility packages on Harvard Dataverse and re-ran each one on a fresh machine: the authors’ own code, the authors’ own data, no changes. 74% stopped with an error. The causes were mundane: a working directory set to someone’s laptop, a package never installed, a file the script expected but the package did not ship. Automatically fixing just the paths and package installs cut the failure rate to 56%. This is computational reproducibility: same code, same data, same results as the paper. It is the check the Reproducible Research team runs on every PRWP package, and it fails for reasons an author can find before submission.

Source: Trisovic, Lau, Pasquier & Crosas, A large-scale study on research code quality and execution, Scientific Data (2022)  ·  code and data

Computational Reproducibility

What the audit checks, and what it does not

Three terms get mixed up, and they are different checks. Computational reproducibility: someone else runs your code on your data and gets the exhibits in the paper. That is what PRWP verification tests, and what the Reproducibility Package skill’s Audit phase (July 16 session) checks for. Replication: someone re-does the analysis from the paper’s description, without your code (see Field Notes). Code review: someone reads the code and asks whether it does the right thing. This issue is about the first.

1.  The audit is read-only. The agent inventories the project, then checks it against the official package checklist and the 14 failure flags the Reproducible Research team sees most often in verification: hardcoded paths, no main script, scattered cd/setwd, unseeded randomness, packages not installed by code, unpinned versions, hand-made exhibits, and so on.
2.  It classifies every data file as an external input or something the code writes, and cross-checks the inputs against the Data Availability Statement. A file the code reads but the package neither ships nor documents is exactly what crashed the scripts in the Big Number.
3.  It maps every table and figure in the manuscript to the script and output file that produce it. Each finding comes as PASS, FLAG, or N/A with the file and line, so you can check it yourself. Then it stops and waits. Proposing fixes is the next phase, and nothing is written until you approve.
4.  An audit-clean package can still be wrong. The audit does not ask whether the regression is the right one, whether the sample restriction matches the paper, or whether a merge duplicated observations. It also says nothing about whether the code is readable or efficient. Those are code review questions, and code review catches problems a reproducibility check never will.
5.  The two checks complement each other. Use the audit to make sure the package runs and regenerates every exhibit; use code review to make sure it computes what the paper says. A later session in the series will cover AI-assisted code review using the DIME peer code review process.

Try This Today  ·  10 minutes

Run the reproducibility skill’s Audit phase on one project you are working on now. Stop before it proposes or makes changes. You are asking one question: would this run on a reviewer’s machine?

1. Open VS Code and confirm that GitHub Copilot or Claude Code responds in the chat panel. The setup guide covers both options.
2. Download the latest skill release. Unzip it and place the full reproducibility-skill/ folder under .agents/skills/ in the project root.
3. Open your project in VS Code. If you prefer to practice first, download the optional demo project and leave its folders unchanged.
4. Ask your coding agent:

Use the reproducibility skill to audit this project. Complete the Audit phase only. Report each finding with the file, evidence, and requirement it relates to. Do not change files.

Pick one FLAG and verify it yourself in the cited file. Mark it confirmed, needs confirmation, or false positive. When the agent asks to continue to Outline, stop there.

Have more than 10 minutes? Read the full report and sort the flags into three groups: would stop a clean run (paths, packages, missing inputs), would change the numbers (seeds, versions, hand-edited outputs), and would confuse the reviewer (README, exhibit list, stray files). Field Notes  ·  beyond the trainings

Replication is a different problem

Kubota and coauthors gave an AI system a published paper, the raw survey data, and the codebook, but no code, and asked it to rebuild the tables from the text alone. For one table it used all 100 attempts and still ended with mismatched sample sizes and significance levels.

That is replication, not the computational reproducibility the audit checks. Field Notes explains why the two should not be confused, what the system’s discrepancy reports did reveal, and where this kind of tool could eventually help.
