# Deep Dive (Track A, Part 1): From Updated Matrices to a Draft Policy Brief

*Background article for AI for Research, Issue 3. Reading time: about 12 minutes.*

The July 30 session introduced **prepare-slides**, a skill that turns manuscripts and results folders into DECDI-branded decks (PowerPoint, Quarto, or Beamer) and waits for your approval before writing files. This piece covers the document version: how to put updated statistical outputs into a refillable Quarto or LaTeX brief so later updates take minutes instead of another afternoon of copy-paste.

You do not need MEGA access. MEGA (or any tool that can call a model with a fixed schema) is one place to run extraction and checks. The same pattern works with a coding agent in your project repo.

**Session skill:** [prepare-slides.zip](https://github.com/dime-worldbank/ai-research-training/releases/latest/download/prepare-slides.zip) · [session page](https://dime-worldbank.github.io/ai-research-training/sessions/ai-skills-slides/)

## 1. Keep structure and numbers apart

A recurring memo is hard to automate when headings and coefficients live in one hand-edited Word file that changes every time the tables change.

| Layer | What it holds | Who edits it |
| --- | --- | --- |
| **Template** | Sections, headings, claim slots, exhibit placeholders, brand | Human, once (then rarely) |
| **Matrix / results** | Coefficients, SEs, Ns, exhibit files regenerated by code | Analysis pipeline |
| **Fill step** | Maps matrix cells to slots; stops if a value is missing | Script or agent with a schema |
| **Verify step** | Checks every number in the draft against the matrix | Script or second pass |

July 30 used the same idea for slides: plan the narrative, approve the figure and table choices, then build. For briefs, freeze the template before you ask anything to write up the results.

## 2. A small pipeline (matrices to brief)

Example flow for a short policy brief with a fixed skeleton:

```text
outputs/tables/*.tex   (or .csv / .json from esttab / modelsummary)
        │
        ▼
  extract_matrix.py / Stata → results/latest.json   ← fixed schema
        │
        ▼
  fill_brief.py  +  templates/policy_brief.qmd|.tex  ← slots only
        │
        ▼
  verify_numbers.py  ← every numeric token must appear in latest.json
        │
        ▼
  quarto render  |  pdflatex                     ← draft PDF
```

A fixed schema is a small JSON file the fill step is allowed to read, and nothing else:

```json
{
  "study": "irrigation_rwanda",
  "wave": "2026-08",
  "main_effect": {"estimate": 0.12, "se": 0.04, "n": 1840, "unit": "pp"},
  "exhibits": [
    {"id": "T1", "path": "outputs/tables/table1.tex"},
    {"id": "F2", "path": "outputs/figures/fig_main.pdf"}
  ]
}
```

The template uses slots:

```markdown
The intervention raised take-up by **{{ main_effect.estimate }}** percentage
points (SE {{ main_effect.se }}, N = {{ main_effect.n }}).
```

If `latest.json` is missing `main_effect.estimate`, the fill step should stop and report the gap.

## 3. Where MEGA or an agent helps

Use a model where language is hard and the output shape is fixed:

| Reasonable to automate | Keep with the author or code |
| --- | --- |
| Turning an annex table into `latest.json`, then checking it against the source | Choosing the identification claim |
| Drafting short non-numeric glue once slots are filled ("Section 2 covers heterogeneity") | Filling in a missing SE or significance star |
| Suggesting a one-paragraph abstract that only cites filled slots | Rewriting the policy recommendation without author review |

Example prompt for the extraction step:

```text
Extract the highlighted estimates from the attached table into JSON matching
schema X. Return JSON only. If a field is not explicitly present, set it to
null and add a note in "_missing". Do not compute new statistics.
```

Then run a check: every non-null number in the brief's rendered text must appear in `latest.json` (you can allowlist boilerplate such as dates or page counts). Same rule as prepare-slides: do not invent missing values.

## 4. Quarto or LaTeX for the template

Either works. Use what your team already compiles.

- **Quarto:** one `.qmd`, YAML for title and authors, placeholders or a pre-pass that writes a `_values.yml` the document includes. HTML and PDF are both easy.
- **LaTeX:** `\input{tables/table1.tex}` for exhibits you already make with `esttab`; a generated `values.tex` (or a few `\newcommand`s) for in-paragraph estimates.

Point the brief at the same `.tex` fragments the paper uses. Do not ask the model to retype `esttab` output as Markdown tables by eye.

## 5. Link to Issues 1 and 2

- **Memory file:** state the brief's path, the schema file, and that coefficients should not be pasted from chat into the brief.
- **Reproducibility skill:** the matrices that feed the brief should come from a package that can regenerate them. Otherwise you automate a stale number.
- **prepare-slides:** the same results folder can feed a deck and a brief. One matrix, two templates.

## 6. A 30-minute build order

1. Pick one recurring output (results memo or short brief).
2. Freeze a 3 to 5 section skeleton with empty slots.
3. Export or hand-build one `latest.json` from this week's tables.
4. Fill once with a script or agent; compile; read the PDF.
5. Add the number check before you rely on the pipeline.
6. Next wave: refresh the matrix and re-run fill, verify, render.

That matches prepare-slides Phase 1 then Phase 2. The first pass takes setup time. Later refills are where you save time.

## One rule

Automate the refill. Keep claims with the author. Without a fixed structure and a number check, "AI wrote the brief" is a fast way to misquote your own table.
