The Big Number
~30%
average task productivity gain from AI tools in controlled trials.
Over 50% for things like programming and writing.

Across controlled field trials reviewed by the OECD, people with AI tools were about 30% more productive on individual tasks. The surprising bit: the biggest gains went to people who were least experienced with the tools, not the power users. So you don’t need to be good at this already. Starting with the memory files and skills from our last two sessions is enough.

Source: CaixaBank Research dossier (May 2026), citing the OECD evidence review

In Case You Missed It

+AI Onboarding: Memory Files & Skills

Quick recap of the two onboarding sessions (June 22 & July 2):

1.  A memory file (AGENTS.md or .github/copilot-instructions.md) is basically an AI ReadMe. Your assistant reads it on every task: stack, conventions, constraints. Write it once.
2.  Put a section for things it always gets wrong. If you keep correcting the same mistake, it belongs there, not in another one-off prompt.
3.  Skills are named, reusable workflows. Think merge checklist or replication audit: multi-step procedures you call up instead of retyping.
4.  Rule of thumb: if you’ve typed the same instruction a third time, make it a skill file.
5.  Keep memory files and skills in version control and review them like code. They’re team assets, not personal settings.

Recording and materials are in the session channel.  |  Nice next step if you were there: add an applyTo-scoped instructions file so your Stata rules only load for *.do files. Details in the Deep Dive below.

Try This Today  ·  10 minutes

Write a short memory file for one active project. Half a page, three sections: preferred packages, folder conventions, and one thing the assistant always gets wrong. Save it as .github/copilot-instructions.md, then do your next task as usual. You’ll usually notice on the first merge.

Grab our template if you don’t want to start from scratch. And if you already have one that works well for panel data, survey pipelines, RCTs, or similar, add it to the repo as an example so the next team can steal it.

Field Notes  ·  beyond the trainings

You probably can’t feel the productivity gain

The ~30% from the Big Number is real. A METR trial with experienced developers shows why you still may not feel it: people’s sense of how much AI helped was off by about 40 percentage points from the measured effect, even right after they finished. (METR has since updated the effect-size estimate — don’t quote that older number. The perception gap is the point.)

For us in DECDI: when we evaluate AI workflows from this series, compare outcomes on similar tasks instead of asking how it felt. The Field Notes piece also covers where AI tends to help, and where review time eats the gains.
