The Big Number
100×
price gap per token between the largest
and smallest Claude model this week

On Anthropic’s price list this week, the largest model (Fable 5.1) costs $10 per million tokens you send it and $50 per million it writes back. The smallest (Haiku 5.5) costs $0.10 and $0.50. A hundredfold gap, in both directions. Opus and Sonnet sit in between at $4 and $2. Enterprise usage is billed at these rates, so the model you pick in the dropdown is the biggest single lever on what your unit pays.

A hundredfold price gap does not mean the small model is a hundred times worse. For proofreading a paragraph or explaining a Stata option, it is usually not worse at all. Impact Analytics’ November 5 training was about matching the model to the job, and two other habits that cut the bill without touching the quality of the work.

Source: claude.com/pricing, checked October 27, 2026. Prices change often; check before you quote them.

In Case You Missed It

Using AI Agents Cost Effectively

Token limits are already a real constraint at the Bank, and use of Claude Enterprise comes out of business unit budgets. Enterprise licenses are not subsidized the way personal ones are, so it matters even more to use them well. Impact Analytics’ November 5 training on using AI agents cost effectively (slides here) emphasized three habits that cut the bill, and why the habits matter more than the current prices do.

1.  Start small on the model. You do not need the most capable model for most tasks. A small model proofreads an abstract, renames variables or reformats a table as well as a large one. A medium model handles most everyday work, like translating Stata to R or debugging a regression script. Keep the large model for work that spans many files or is genuinely ambiguous. Move up only when the smaller model falls short.
2.  Write a memory file. Without one, the agent spends tokens on every request rediscovering basic facts about your project: which language you use, where the code folder is, whether the data is in the folder. A memory file (AGENTS.md or CLAUDE.md) tells it once. It takes about five minutes to write, and it also makes a smaller model good enough, because the agent is no longer spending its effort on discovery.
3.  Start a new chat for each new task. Models keep no memory between requests. Every time you send a message, the whole conversation so far is sent and processed again. Ten tasks in one chat means the tenth pays for the previous nine. The test: does my next request need anything from this conversation, beyond what is already in my files? If not, open a new chat. To reuse a good prompt, paste it into the new chat.

A fourth point from the training, for projects that keep feeding the agent Word, Excel or PDF files: convert them to plain text once, so you do not pay for the conversion on every request.

What the habits add up to

In the training’s case study, an agent did the same three everyday tasks on a small, fictional RCT project three ways: fix a broken balance-table script, proofread an abstract, and write a README.

Workflow Habits Tokens Cost
One long chat, largest model none 675k $0.65
New chat per task 3 333k $0.43
New chat, memory file, model picked for the task 1, 2 and 3 191k $0.05

Using all three habits cut the cost by about 12 times, and the work was just as good. One detail: the same prompt, “Can you proofread the abstract?”, cost 229k tokens as the second task in a long chat and 48k in a new one. These are single runs on a small project, so treat the exact numbers as an illustration. You can rerun the case study yourself.

How do you know how much you are spending?

Watch your own usage for a couple of weeks and you will learn which of your tasks are token-hungry. GitHub Copilot’s chat panel in VS Code shows how full the context window is. At the end of a task, under 5% suggests a larger model than you needed; over 95% suggests one too small, where details were probably lost. In Claude Code, /cost shows what the current chat has spent and /context shows what is filling the window. Claude’s usage page shows how much of your allocation is left.

Try This Today  ·  10 minutes

Make one routine task cheaper, and find out whether it got worse.

1. Write down your numbers. Claude: Settings, then Usage. GitHub Copilot: the premium requests left this month. Put them in a text file with today’s date. One line. You will want the trend later.

2. Look at what you are carrying. In the chat session you have open right now, check GitHub Copilot’s context meter, or type /context in Claude Code. If most of it is tool output from tasks you finished an hour ago, that is what you have been paying to resend on every request since.

3. Start a new chat and pick a small model. Choose a routine task: proofread a paragraph, rename variables to match a convention, explain an error message. Switch the model picker to the smallest model on offer before you send it.

4. Judge the answer as strictly as you would the big model’s. Did it get anything wrong that the larger model would have got right? If not, that task has a new default. Add that to the text file too.

Have more than 10 minutes? Open the memory file of the project you spent most on this month. Add the three things the agent had to ask you, or got wrong, this week. Or do the training’s five-minute self-audit: look at your last ten chats and count the long threads, the repeated corrections and the large models used for small jobs. Field Notes  ·  beyond the trainings

Same model name, different answer

Switching to a smaller or newer model is the fastest way to cut the bill. For drafting and debugging, that is all it is. But if you used a model to code survey answers or classify documents, a different model can hand you different data.

Three political scientists re-ran the same text-coding tasks on the same models every month for most of 2024. The AI beat crowdworkers on accuracy and lost on stability. Fixing the temperature did not help, one model stopped existing mid-project, and the re-estimated coefficients came out a third the size.
