Three Questions Before Every Task

  1. Which tool? Decide by data sensitivity first, convenience second.
  2. Which model? Decide by task size: start medium, go down if the task is mechanical, go up only when the smaller model fails.
  3. Which setting? Decide how much context the agent needs from you:
    • A good prompt is enough for a one-off task: name the file, the goal and what not to touch.
    • A memory file for work you keep doing in the same project: language, folders, key variable names.
    • A skill for instructions you reuse across projects, or have pasted three times.

And keep the habit from earlier: a new session for each new task.

What Counts as a New Task?

Ask yourself: does my next request need anything from this conversation – beyond what is already in my files or memory file?

  • No → new session. The earlier discussion would just be trailers.
  • Yes → stay. The agent needs what you just worked out together.
Example Same task or new?
Draft slide 5, then fix a typo on slide 5 Same – builds directly on the draft
Draft slide 5, then draft slide 9 on a different topic New – only the style carries over, and that belongs in a memory file or skill
Debug a regression, then write the README New
Batch 1 of a review, then batch 2 with the same instructions New – reuse the prompt, not the chat

Case Study: An Afternoon on the Cash Plus RCT

The Setup

A research assistant on a (fictional) impact evaluation: cash transfers plus nutrition coaching in rural Kenya, 60 villages, 1,200 households.

The project folder

  • R scripts: clean, balance table, ITT regressions
  • Baseline and endline survey data
  • Pre-analysis plan, field notes, two old paper drafts
  • The current abstract

Three everyday tasks

  1. Fix the balance table script (it crashes on wrong variable names)
  2. Proofread the abstract
  3. Write a README
  • We ran the same three tasks three ways in Claude Code and recorded every token.
  • We ran it using claude personal and enterprise and the results are the same, with some differences on specific tokens as that will always vary from run to run. The reported results are using Claude Enterprise.

The Memory File We Used for C

# Cash Plus RCT
Cluster RCT of cash transfers + nutrition coaching in rural Kenya.
60 villages (30 treated), 1,200 households. Randomized at village level.

## Language and packages
- R only: dplyr, fixest, here. Paths built with `here::here()`.

## Folder structure
- `code/00_main.R`: runs everything in order (01_clean → 02_balance → 03_analysis)
- `data/raw/`: `baseline_hh.csv`, `endline_hh.csv` (merge on `hhid`)
- `docs/`: pre-analysis plan, field notes, old drafts. Don't read unless asked.

## Data
- Source: household surveys, baseline (2024) and endline (2025). De-identified; can be shared.
- Every README must include a data availability statement.

## Key variable names
- Treatment: `treatment` (0/1). Cluster: `village_id`. ID: `hhid`.
- Baseline: `hh_size`, `head_female`, `head_educ_yrs`, `consumption_pc`, ...

Five minutes to write with a lot of impact (you will see).

What Drove the Difference

  • New task. The same prompt, “Can you proofread the abstract?”, cost 229k tokens as the second task in a long chat and 48k in a fresh one: almost 5x, only from carrying task 1 along.
  • Setting. Without a memory file, the agents in A and B read the pre-analysis plan and the field notes, which none of the tasks needed. With it, the agent in C opened 4 small files plus the header row of the data.
  • Model. Haiku proofread the abstract and wrote the README without problems. Neither task needed Opus.
  • Vague prompts are a coin toss. Asked only to “proofread”, A fixed the typos but B just listed them, so a real user would need one more turn. The specific prompt said “edit the file”, and C did.

Read the Numbers

  • One run per workflow. Runs vary: tasks A1 and B1 had identical setups and still differed by 14% (145k vs 127k).
  • Claude Code has a floor. Every request sends a large set of built-in instructions, so even the shortest task cost ~50k tokens here. Chat tools start lower, but the patterns are the same.
  • The project is fictional and small. This grows with every task you add to a chat, so on a real project with longer chats the gap tends to widen.
